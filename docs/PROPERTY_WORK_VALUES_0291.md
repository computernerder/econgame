# Property work condition context — 0.29.1

The Book property work form now shows the selected building's current system condition alongside the controls. All eight system options include their actual rating out of 100. A comparison panel shows condition, age, attention level and any active work; selecting a card chooses that system in the booking dropdown. The selected system also identifies its required license or qualification.

Changing the property refreshes all eight ratings, labels and work indicators without submitting or losing the selected work type or contractor. Property-specific repair links retain their selected property/system and render the same context immediately. Current conditions come from the same read model used by the property page; they are distinguished from dated inspection estimates. The displayed simulation date identifies the snapshot. Empty properties/lots show an explanation rather than invented ratings.

Conversion use is now hidden for ordinary repairs even when the existing form layout styles would otherwise override the hidden attribute. The comparison layout uses four, two or one columns according to viewport width. Existing booking costs, qualifications, effort, payments, review/confirmation and simulation behavior are unchanged. No save migration is needed.

Validation: **40 tests passed**, with two existing dependency deprecation warnings, using the project's Python with `-X utf8 -B -m pytest -q -p no:cacheprovider tests/test_property_work_context.py tests/test_ui_workflows.py tests/test_property_scale.py tests/test_template_updates.py tests/test_money_display.py`. New coverage compares rendered values against two distinct properties' saved conditions, checks active work and focused system selection, limits context to selectable properties, handles no owned buildings, and verifies page reads do not mutate the world.
